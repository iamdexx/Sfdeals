# Riverside (Riverside County) sources

Working, free, unattended:
- Riverside County Assessor parcel layer `gis.countyofriverside.us/arcgis/rest/services/parcels/Parcels/MapServer/0` (914k parcels; `APN` 9 digits no dashes, `SITUS_STREET`, `CITY`, `ZIP_CODE`, `PRIMARY_OWNER`, `MAIL_STREET`, `MAIL_CITY`, `CLASS_CODE` text land use, `LAND` and `STRUCTURES` assessed values). Houses are `CLASS_CODE IN ('Single Family Dwelling','Condo or PUD','SFD with Secondary Unit(s)','HOMESITE/< 1 ACRE','HOMESITE/1-4.9 ACRES','MH on Foundation (MF)')` (about 700k; Single Family Dwelling alone is 583k). Absentee pulled server side as `MAIL_STREET <> SITUS_STREET` (250k rows, about 2.5 minutes at 2000 a page).
- Treasurer-Tax Collector tax sale inventory `gis.countyofriverside.us/arcgis_mapping/rest/services/App_TaxSaleInventory/TaxCollectorInventoryWebApp/FeatureServer/0` (8.9k parcels subject to the power to sell: `PIN`, `GEO_CD`, `SITUS` with city and zip, `REDEMPTION_AMOUNT`, `LAND`, `STRUCTURE`, `CLASS_CODE`, `AS_OF_DATE`). Residential classes are 1,181 rows / 678 parcels, 139 of them with a structure assessed at 40k or more; those become the hot leads (137 at first run). The rest are HOMESITE lots with no structure value, dropped by `min_value`.

Gotchas:
- The tax sale layer has `maxRecordCount` 1000 and the generic puller stops after a short page, so the signal is split into two config entries (same name and label) that each return under 1000 rows. If the residential rows grow past 1000 in either half, split again.
- Join on `GEO_CD`, not `PIN`. `PIN` is the Tax Collector's assessment number; when a parcel was split or merged `GEO_CD` carries the current Assessor APN (6.8k of 8.9k rows differ, almost all timeshares and common areas). Checked 8 single family rows: all 8 `GEO_CD` values resolve to the right house in the parcel layer.
- The tax sale FeatureServer returned HTTP 500 `Error performing query operation` on roughly half the queries for a few minutes one evening and then went back to 100 percent. `fetch()` only retries transport errors, so a run can fail on that layer; just rerun. A `MapServer` twin of the same layer exists at the same path if the FeatureServer stays flaky.
- `MAIL_CITY` carries city, state and zip in one string (`CORONA CA 92882`), and the layer has no separate mailing state or zip fields, so `mail_state` and `mail_zip` are empty and the "out of state" flag never fires. `MAIL_CITY` is shown on the card as is.
- `STRUCTURES` is the Prop 13 assessed structure value, not market. Long held houses show 30k to 80k. `min_value` is 40000 so some old houses with low base year values are dropped; lower it if the list looks thin.
- No sale date, sale price, year built or living area on the parcel layer, so no cash buyer list. Those fields live in the OpenData Assessor tables (`OpenData/Assessor/MapServer` 70 CREST_GENERAL, 80 CREST_PROPERTY_CHAR with `YEAR_BUILT` and `LIVING_AREA`, 100 CREST_TAXYEAR with `HOMEOWNERS_EXMPT`), keyed by `PIN`; a second pull and join would add year, sqft and a homestead `occ` flag.
- Lookup: RivCoView (`rivcoview.rivcoacr.org`) is a Spatialest app; the `#/Property-Search/search/mv_Location:PIN/<apn>` route opens the search tab but does not run the search, so the card prints the PIN to paste. The Tax Collector search (`ca-riverside-ttc.publicaccessnow.com/PropertySearch.aspx`) is a POST form with no deep link.

Dead ends:
- City of Riverside code enforcement: the city ArcGIS org (`services.arcgis.com/Fu2oOWg1Aw7azh41`) only publishes code enforcement AREA polygons (`CodeEnforce2018SIEBELService`, `CodeEnforceAreas`, 8 districts) and a 2007 `PotentialVacantParcels` layer (518 rows). No parcel level case layer; cases live in the city's Accela / Siebel portal behind a search form.
- `gis.rivco.org/arcgis/rest/services` is a web page, not a REST root. `gis.countyofriverside.us/arcgis_public/.../App_TaxCollector/TaxCollector` no longer exists.
- `gis1.countyofriverside.us/arcgis/rest/services/OpenData/ParcelBasic/MapServer/0` answers with no fields.
